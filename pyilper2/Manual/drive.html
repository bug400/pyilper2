Drive Tab

Description

This virtual device emulates either an HP82161A cassette drive, an HP9114B disk drive (without the SS/80 command set), or a virtual HDRIVE1 device to access files on an LIF image file.

The directory listing of the current LIF image file is displayed on the tab. The listing is updated if the drive has been idle for 3 seconds. The column headers can be checked to get a sorted list of the directory.

The virtual devices have the following HP-IL configuration and their supported LIF image file layouts. A layout describes internal characteristics of a LIF image files and thus also the total capacity.

Specifying the Drive Type

The drive type is selected from the checkbox group. If another drive type is enabled, the currently used LIF image file is unmounted. Please run a RESTORE IO command so that the controller is aware of the change in drive type.

In most cases you should apply the HDRIVE1 drive type, since it supports the most LIF image file sizes. Apply the HP9114B drive type if you use software that requires compatibility with that device. Use the HP82161A drive type if the controller is an HP-41.

Mounting LIF image files

pyILPER requires a valid LIF header when mounting existing LIF image files. The LIF header specifies the layout of the LIF image file. A valid LIF header includes:

  • The LIF identifier 0x800 at offset 0
  • The media size information (number of tracks per surface, number of surfaces, and number of blocks per track) starting at offset 24

If the LIF file header is missing or incomplete, the mount of the file will be rejected. Invalid LIF headers result from the file having been created either with the HP-41 or with faulty versions of the HP-71 IL module. In this case, you should create a backup file and repair the header using the Fix Header of LIF Image Files function in the Utilities menu.

For each drive type, only LIF image files with the layouts listed in the table above can be mounted.

Note: the HP-41 can only access the first 130K bytes of larger disk media. The documentation of the HP9114B disk drive includes a FOCAL program that allows you to access content larger than 130K bytes.

Initializing LIF image files

It is generally recommended that you let pyILPER create empty LIF image files with the Initialize LIF Image Files function of the Utilities menu. This allows you to generate all LIF image file layouts listed in the table above.

If you want to initialize a LIF image file using an HP-IL controller, the resulting LIF image file is initialized with the standard layout of the current device type (shown in bold in the table above).

The process is as follows (HP-71): select the desired drive type, enter a non-existing file name as the LIF image file, and do a RESTORE IO and initialize the medium from the controller.

pyILPER takes care that incorrectly generated LIF image file headers are corrected automatically.

Device Controls

The drive tab has the following controls:

  • LIF image file Change button: mount a disk file that contains the image of an LIF file. If a nonexistent file was specified, the medium must be initialized by the controller. Note: the file is only opened by pyILPER during HP-IL read or write operations.
  • Drive type combo box: Choose the proper drive type that shall be emulated (see above). The LIF image file must be reopened after the drive type was changed.
  • Device enabled: If checked, the virtual HP-IL drive is available and can be used as an HP-IL device. The HP-IL loop must always be reconfigured after activation or deactivation.

Tab configuration menu

  • Font size: Set the font size of the directory listing. If Default is selected, the setting of the pyILPER configuration is used.
  • Character set: select the character set that is emulated. See the documentation of the Terminal Tab.

File Management Functions

are a convenient way to edit LIF image files and the files stored within them. The features are only enabled if both a compatible version of the LIFUTILS (at least Version 2.0.0 is required) are installed and the drive is not active. A drive is inactive if either the loop has stopped or the Device enabled checkbox is unchecked. This ensures that HP-IL commands and file management functions are not executed simultaneously.

To use the LIF image file management functions, it is recommended that you know the basics about LIF image files, LIF files, and the LIFUTILS. Reading the LIFUTILS tutorial is a good starting point.

File Management Functions for the mounted LIF Image File

  • Pack the mounted LIF image file (very fast!)
  • Import a file from the local file system into the mounted LIF image file
  • Label the mounted LIF image file
  • Directory Listing outputs the directory listing to a PDF file

For the Import function there are a number of preprocessing options to prepare a wide variety of file types for import into a LIF image file:

  • Convert ASCII text files to formats compatible with HP-41, HP-71, and the HP-75
  • Convert HP-41 ROM files to HEPAX, Eramco MLDL-OS, and the HP41-CL format
  • Process HP-41 FOCAL raw files
  • Compile HP-41 FOCAL source files

File Management functions for files stored in the LIF Image File

Use the file context menu (right mouse button click on selected file in the directory listing) to execute the following functions:

  • Purge the selected file
  • Rename the selected file
  • Export the selected file to the local file system
  • View the contents or summary information of the selected file. Note: this entry is only available for certain file types. To view text files, the proper character set must be configured in the configuration menu.
  • Barcode output for HP-41 program and SDATA files to a PDF file.

For the Export there are the following post-processing options depending on the file type:

  • Conversion of HP-41, HP-71, or HP-75 text files to ASCII text files
  • Unpacking HEPAX or ERAMCO MLDL-OS ROM files
  • Create raw instead of LIF files

The LIF image file management functions only support file names that contain letters and digits. Unfortunately, the HP-41 IL-module is less strict, and file names may contain other characters. You can rename these files to proper LIF file names.
